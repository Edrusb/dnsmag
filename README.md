# dnsmag
Simple command-line tool to automatically generate bind DNS configuration: named.conf, forward and reverse zones

## Usage

Given a parent zone, like <code>hpc.lab</code>, users can create sub-domaines, like <code>demo1</code> (sub-domaines are simply called zones in the following) and
in these zones add (or remove) names, like: <code>host1</code>. Doing that will create in the DNS an entry <code>host1.demo1.hpc.lab</code> (both forward and reverse zones)
and user will be returned the IP address to use for that entry:

>
> \# dnsmag add-rec demo1 host1<br>
> The record host1 in zone demo1 has been associated to the IP 172.16.42.1<br>
> \#

and of course users can easily delete an existing entry:

>
> \# dnsmag del-rec demo1 host1<br>
> Record host1 has been removed from zone demo1<br>
> \#

But first, you guessed, the zone <code>demo1</code> must have been created given a subnet to manage. At current time only /24 IPv4 subnets are supported:

>
> \# dnsmag add-zone demo1 172.16.42.0<br>
> Zone demo1 added<br>
> \#
>

Last, to properly interact with the named process, the location of the zones files and of the name of the named.conf-like file to generate has to be
provided when initializing dnsmag. The initialization also requires some information used to setup the SOA records expected in each zone file.
All the information provided at initialization is stored in a database file, where will also be stored the different zones and for each
zone the name-IP associations:

>
> \# dnsmag init hpc.lab /etc/bind/named.conf.dnsmag /etc/bind/Dnsmag-Zones jumphost.hpc.lab hostmaster.hpc.lab
>

in the previous command-line, we tell dnsmag to create a database with:
* the DNS domain under which zones will be created: <code>hpc.lab</code>
* the path to the file that will be generated (and overwritten when necessary) by dnsmag <code>/etc/bind/named.conf.dnsmag</code> and which will have be included from the bind main configuration file (usually /etc/bind/named.conf)
* a directory where will be created, updated and eventually deleted the DNS zones files referred from the <code>/etc/bind/named.conf.dnsmag</code> file mentioned above
* the nameserver (here jumphost.hpc.lab) to give in the SOA record for zones generated by dnsmag
* the hostmaster email in the form expected by the SOA records for the zones generated by dnsmag

By default the database is expected to be at <code>/usr/local/etc/dnsmag.json</code>. But this can be changed to another place
by mean of the <code>DNSMAG_BASE_PATH</code> environment variable:

>
> export DNSMAG_BASE_PATH=$HOME/dnsmag.json
>

To complete the picture, the <code>rnd</code> command should be available from the PATH environment for dnsmag to trigger bind to reload its configuration when necessary
and the <code>/etc/bin/named.conf</code> should include something like the following (the added line is in bold below) for it knowns about the zones files generated by dnsmag:

> // This is the primary configuration file for the BIND DNS server named.<br>
> //<br>
> // Please read /usr/share/doc/bind9/README.Debian for information on the<br>
> // structure of BIND configuration files in Debian, *BEFORE* you customize<br>
> // this configuration file.<br>
> //<br>
> // If you are just adding zones, please do that in /etc/bind/named.conf.local<br>
><br>
> include "/etc/bind/named.conf.options";<br>
> include "/etc/bind/named.conf.local";<br>
> include "/etc/bind/named.conf.root-hints";<br>
> <b>include "/etc/bin/named.conf.dnsmag";</b><br>
> 

## Requirements

To build dnsmag you will need:
* make (For Debian users: <code>apt-get install make</code>)
* C++ compiler, (For Debian users: <code>apt-get install g++</code>)
* Niels Lohmann's famous [json "library"](https://github.com/nlohmann/json). Under Debian <code>apt-get install nlohmann-json3-dev</code> should do the trick
  

## Building dnsmag

>
> make
>

## Installing dnsmag

>
> make install
>
